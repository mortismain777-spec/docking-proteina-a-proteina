# Suggestions, bug reports and contributions

**English** | [Español](CONTRIBUTING.md)

Suggestions, comments and bug reports are welcome from the start. If something is confusing, you encounter a problem or you have an idea, open an [Issue](https://github.com/mortismain777-spec/docking-proteina-a-proteina/issues) so it can be reviewed and considered for inclusion. You do not need to have a solution first. Issues may be written in English or Spanish.

Describe what you expected, what happened, the app version and the steps to reproduce it. For a proposal, explain the need it addresses. Before sharing logs, remove other people's email addresses, private paths, credentials, tokens and sequences that should not be public. Send private information to mortismain777@gmail.com instead.

Code, documentation and scientific collaborations are welcome. For large changes, open an Issue first to agree on scope. Proposals are assessed for usefulness, feasibility, evidence and relevance to the project; submission does not guarantee immediate inclusion.

For code contributions, use a branch, explain the change and its checks, and run the relevant tests described in the README. Retain authorship notices and identify the source and license of external components. Do not include HDOCKlite executables or private data in a pull request. For documentation changes, update both language versions or clearly identify a translation that still needs updating. Keep CSV headers, accepted values, flags and filenames unchanged unless the application itself changes.

Contributors retain the rights they hold in their contributions. Before incorporation, the license and any permissions needed for future business agreements must be agreed. Copyright assignment is not presumed, and commercial permission over third-party code is not granted automatically.
